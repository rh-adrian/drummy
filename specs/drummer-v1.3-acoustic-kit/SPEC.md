## Overview

Add a real acoustic drum kit ("Acoustic") alongside the 10 drum machines, sourced from
the Salamander Drumkit — multi-velocity-layer recordings of a real kit. The compiler
maps each hit's velocity to an actual soft/medium/hard *recording* (via an aligned
`.n()` grid) instead of just scaling one sample's gain, including real ghost-note
snare samples and a velocity-split open hat (semi-open below, washy full-open at high
velocity). Samples stream from raw.githubusercontent (CORS-enabled, pinned commit)
exactly like the existing CDN samples — nothing is vendored, the repo stays MIT.
Three new drum voices join the vocabulary: cb (cowbell — also unlocks the classic
cowbells on the machine kits via tidal-drum-machines), ch (china), sp (splash).

## Goals / Non-Goals

**Goals**: an acoustic bank that audibly responds to velocity like a drummer;
new voices cb/ch/sp end-to-end (schema → compiler → grid → tools teaching text);
licensing recorded (CC BY-SA 3.0, attribution in SAMPLES.md); all existing kits and
invariants untouched.

**Non-Goals**: vendoring audio (D-7 stands); offline mode; new articulations as
voices (ride bell, snares-off, foot hat, chokes — future spec if wanted); humanize/
feel algorithms (velocity/micro stay the LLM's job); multiple acoustic kits.

## Functional Requirements

- FR-1: `Acoustic` is a selectable bank (play_groove/set_kit/list_kits) with voices
  bd, sd, rim, hh, oh, lt, ht, rd, cr, cb, ch, sp (no mt, no cp — availability
  reported honestly by list_kits).
- FR-2: A committed sample-map JSON (`page/acoustic.json`, index-only: `_base` +
  file lists) maps each voice to exactly 8 slots ordered soft→loud, curated from the
  Salamander velocity layers with round-robin takes spread across same-layer slots.
  Generated by a re-runnable script pinned to commit
  8b6faa8847b4c02f4b5dd42c1836c28ffbe89d33; the JSON is committed, the script kept.
- FR-3: For the Acoustic bank the compiler emits an aligned `.n()` grid picking the
  slot from each hit's velocity (slot = min(7, floor(vel*8))), with gain = vel like
  every other bank (originally specced as a softened curve; overturned by D-29 —
  the source files are peak-normalized, so gain must carry the full dynamics).
  Machine banks compile exactly as before (no `.n()` — byte-identical output).
- FR-4: sd's lowest slots are the real ghost-note recordings (schema doc already
  teaches vel 0.2–0.4 = ghost); oh slots 0–5 are the semi-open ladder, slots 6–7
  full open (velocity-split, D-26).
- FR-5: New voices cb/ch/sp: schema DRUM_ABBRS, kits.ts DRUMS (teaching names),
  grid ROW_ORDER (cymbals ch/sp near cr; cb in the percussion group), tool
  descriptions. cb resolves on machine kits via tidal-drum-machines (`*_cb`); ch/sp
  exist only on Acoustic and report unavailable elsewhere.
- FR-6: The page loads the acoustic map at prebake alongside tidal-drum-machines
  (served by the sidecar at `/acoustic.json`, `_base` remote) and `warmBank`
  pre-fetches Acoustic hits like any other bank.
- FR-7: list_kits reports Acoustic availability from the local map (no network);
  machine-kit availability behavior unchanged.

- D-28 (risk, accepted): samples are FLAC. Chrome decodes FLAC in decodeAudioData
  (e2e covers it); Safari support is probable-but-unverified. If Safari fails, the
  fallback is a WAV mirror hosted in a SEPARATE repo under CC BY-SA (verbatim-ish
  redistribution with attribution is permitted; this repo stays MIT either way).
- D-29 (M2 discovery, overturns FR-3's softened-gain idea): every Salamander file is
  peak-normalized to 1.0 (verified by decoding ghost/MP/F/FF snare files: all peak
  1.000). The velocity layers therefore carry TIMBRE, not level — so the compiler
  keeps gain = vel (identical rule to machine banks, one mental model for the LLM)
  and `.n()` supplies the timbre. Proven in e2e by peak ratios matching vel ratios
  AND FF↔ghost waveform decorrelation (corr 0.544; same-recording would be ≈1).
